# 站点规模与「什么时候才需要分页」

这份文档把几个**原本只凭感觉判断**的决定，换成可复算的数字。
测量环境：仓库 `public/` 产物，gzip 用 `gzip -6`。

## 当前规模（2026-10）

| 项 | 数值 |
|---|---|
| 文章数 | 17 |
| 最长文章 | 2043 词 / 69 KB HTML（cyberpunk-ui-design） |
| 最短文章 | 368 词 / 4 KB（wetdry-cleaner-battery-test） |
| `/posts/` 列表页 | 单页渲染全部 17 篇，**无分页** |
| `/posts/` 未压缩 | 13.9 KB |
| `/posts/` gzip 后 | **3.7 KB** |

## 列表页体积的增长模型

从真实产物里量出，而不是估：

- 单张 `post-card` 平均 **488 B**（未压缩）
- 页面固定部分（框架、导航、页脚）约 **3359 B**

因此 `未压缩体积 ≈ 3359 + 488 × 文章数`。

反推「什么规模下才值得做分页」：

| 目标未压缩体积 | 所需文章数 |
|---|---|
| 50 KB | **约 98 篇** |
| 100 KB | **约 203 篇** |

## 结论：现在不做分页

当前 17 篇，`/posts/` gzip 后仅 3.7 KB —— 距离 50 KB 的参考线还差约 **6 倍**。
**不做的理由是有数字的，不是"觉得不用"。**

复查方式：文章数接近 60~80 篇时重跑一次上面的量法；
或直接看 `/posts/` 的 gzip 体积是否超过 ~20 KB。

## 总传输（gzip，实测）

| 资源 | gzip 后 |
|---|---|
| 首页 HTML | 3.6 KB |
| chinese.css | 12.7 KB |
| site.js | 3.2 KB |
| **首页合计** | **19.0 KB** |

CSS 是最大单项（12.7 KB），但它**全站共用且缓存 10 分钟**，
后续页面访问的实际成本只有 HTML（3~10 KB）。

## prefers-reduced-motion

全站 111 页在 `prefers-reduced-motion: reduce` 下：
- **0** 个仍在播放的 CSS 动画
- **0** 个仍在进行的 transition

实测弹幕（唯一的持续动画）：
| 设置 | animation | 800ms 内位移 |
|---|---|---|
| 默认 | `passing 16s ×infinite` | **96 px** |
| reduce | `passing 1e-05s ×1` | **0 px** |

JS 层没有装饰性动画：滚动进度条与顶栏样式切换属于**状态指示**，
随滚动更新是预期行为，不受 reduce 影响。

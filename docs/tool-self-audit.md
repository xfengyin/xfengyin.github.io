# 验证工具的自检（工具坏了不能长得像健康）

## 为什么要做这件事

第 18 轮发现**对比度检测工具本身在系统性误报**：它把"顶栏白字压在深青渐变上"
算成"白底白字 1.00:1"，而这个假阳性在报告里**连续出现了好几轮**，我一直口头带过没有深究。
教训：**一个坏掉却输出 ok 的检测器，比没有检测器更危险。**

所以要对每个工具做一次「故障注入」：故意植入它该发现的缺陷，看它报不报。
只测"正常时安静"是不够的——一个永远不响的报警器和没有报警器是一样的。

## 2026-10-13 自检结果

| 工具 | 植入的缺陷 | 是否抓到 |
|---|---|---|
| `check-links.py` | 指向不存在文章的链接 | ✓ 抓到 1 处断链 |
| `content-drift-check.py` | 「共 99 篇」+ 不存在链接 | ✓ 抓到 2 处漂移 |
| `declared-values.cjs` | JSON-LD `image` 改回相对路径 | ✓ 抓到 3 处 |
| `viewport-check.cjs` | 插一个 900px 宽的固定元素 | ✓ 3 个视口均报溢出 |
| `hit-area.cjs` | 把深色按钮改成 8×8 并禁用 `::after` | ✓ 判为 ✗ |

额外发现：**非法日期会被 `zola build` 直接拦住**，到不了 `declared-values` 那一层 ——
构建本身就是第一道闸，这是好事（多层防护）。

## 做故障注入时必须注意的两个坑（都踩过）

1. **注入会被构建覆盖。**
   我第一次测 `check-links.py` 时改了 `public/` 里的产物，然后跑脚本，
   而脚本前一步（或我上一条命令）跑了 `zola build`，产物被重新生成、注入消失，
   于是得到"没抓到"的**假阴性**，差点误判工具坏了。
   → 规矩：**注入必须发生在构建之后**，且注入后立刻确认文件里确实有那段内容。

2. **压缩后的 HTML 里没有 `</body>`。**
   我想用 `replace('</body>', ...)` 注入，但 Zola 开了 `minify_html`，
   HTML5 的 `</body>``</html>` 是可省略的，产物里根本不存在这个字符串，
   替换静默失败（`in` 检查才发现）。
   → 规矩：注入的锚点要选**确定存在**的东西（如文件末尾追加），并在注入后断言成功。

## 复跑方式

改动任何一个工具或模板后，建议按上面表格里的方式重新注入一遍验证。
（这些注入都是一次性的，测完必须还原 —— 本轮全部已还原，工作区已验证为 0 改动。）

## 第 20 轮补充：axe 自身的审计

### 1) 发现原来的规则集过窄

`/tmp/a11y-browser/axe-run.cjs` 一直只用
`['wcag2a','wcag2aa','wcag21a','wcag21aa','best-practice']` ——
**漏掉了 WCAG 2.2**（`wcag22a`/`wcag22aa`）、2.1 AAA、ACT、Section 508。
而 2.5.8 目标尺寸（我第 11 轮手工修的项）恰恰属于 WCAG 2.2 AA。

用**完整规则集**重跑 111 页，结论与之前一致：
```
规则集: wcag2a,wcag2aa,wcag2aaa,wcag21a,wcag21aa,wcag21aaa,wcag22a,wcag22aa,best-practice,ACT,section508
扫描页面 111，有违规的 4
  [critical] label × 65  出现在 4 页
```
→ 说明之前"只报了 label"的结论**没有因为规则集窄而漏报**，可以放心。
（这条结论本身值得记：不是"我猜没漏"，而是换宽规则集重跑验证过。）

### 2) axe 的故障注入：确认它能抓到

植入 3 类必然违规（无 alt 图片 / 空按钮 / 第二个 h1），axe 全部报出：
```
[critical] image-alt   × 1
[critical] button-name × 1
[moderate] region      × 2
```
→ axe 是活的，不是"永远报 ok"。

### 3) ⚠️ 重要限制：axe 在本机**测不了 target-size**

本机 axe 跑在 **jsdom** 里，**没有布局引擎**——所有元素的尺寸都是 0。
实测：植入一个 `6×6` 的按钮后，`wcag22aa` 规则集仍然 **0 违规**。

这不代表"目标尺寸达标"，而是**axe 在这个环境下根本量不出来**。

→ 这正是我用自写 `hit-area.cjs`（真实 Chrome + `elementFromPoint` 量实际可点区域）的理由 ——
  它**不是冗余**，而是覆盖了 axe 在 jsdom 下看不见的一整类问题。
  该工具已单独做过故障注入（把深色按钮改 8×8 → 正确判 ✗）。

### 结论：两套检测互补，缺一不可
| 维度 | 用什么测 | 为什么 |
|---|---|---|
| 语义/ARIA/标签/标题层级 | axe（jsdom 够用） | 不依赖布局 |
| 目标尺寸 / 实际可点区域 / 溢出 | hit-area.cjs、viewport-check.cjs（真实 Chrome） | **依赖布局**，axe 在 jsdom 下量不到 |
